# v1.0---测试流量与真实数据未分层-fix经验积累

## 现象

- AI 测试平台的 503 次运行全部是测试数据，无法区分“AI 自动测试”“人在平台上人工体验”“线上真实用户”。
- 测试目标直接指向生产 `https://shang.bettery.cn`，使用真实 C 端账号；尚品汇库里没有 `is_test` 标记，测试会话和真实会话混在一起。
- 平台 `AgentRun` 强绑定 `case_id`，真实会话无法入库；详情页也没有“来源”字段。

## 根因

1. 平台数据模型只有测试用例运行，没有 `sourceType/environment/externalSessionId` 等来源字段。
2. 平台请求没有携带测试标记，尚品汇无法在 session/run 层区分测试流量。
3. 尚品汇生产会话没有推送链路，平台拿不到真实数据。
4. 平台统计把测试运行和真实会话放在同一通过率口径里，指标会被污染。

## 修复

- 平台 `agent_runs` 增加 `source_type/environment/conversation_id/external_*`、`is_test`、`pii_masked`、`metadata`、
  `ingested_at`，`case_id` 改为可空；新增 `agent_conversations`、`agent_ingest_events`。
- 平台 `shangpin` 适配器建会话/发消息统一带 `X-Agent-Test: ai` 和 `X-Agent-Test-Run-Id`。
- 尚品汇 `chat_session` / `agent_run` 增加 `is_test/test_source/test_run_id`；`ChatController` 读取请求头；
  测试会话强制独立，不误关真实进行中的会话。
- 尚品汇新增 `platform_outbox` + `PlatformWebhookService`，HMAC 签名、幂等 eventId、失败指数退避。
- 平台新增 `/agent-test/ingest/shangpin` 接收 webhook，按会话归并、按 run 幂等，做手机号/身份证/邮箱二次脱敏。
- 平台 Agent 测试页增加“测试数据 / 真实数据”视角：
  - 测试数据：AI 自动执行 Golden/用例
  - 真实数据：人工体验（`human_manual`）与生产会话（`production`）
  - 真实会话支持人工判定、转测试用例
- 平台 summary 只统计 `source_type=ai_test`；真实数据单独 `/data-summary`。

## 回归

- 平台新增迁移 `a1f2b3c4d5e6_agent_data_sources`，本地 `alembic upgrade head` 通过；29 条后端测试通过。
- `POST /agent-test/ingest/shangpin` 本地实测：首次写入 1 个会话/1 个 run，重复 eventId 返回 duplicate。
- 平台真实数据页实测：列表、详情、人工判定按钮、转测试用例按钮可用。
- 尚品汇 `V28__agent_test_data_marking.sql` 已加入，字段默认值兼容旧数据。
- 测试流量 webhook 默认不推送；人工体验 `testSource=human` 会推送并进入真实数据看板。

## 经验

- “测试/真实数据”不是前端加个标签，必须同时改数据模型、请求标记、采集链路和指标口径。
- 测试流量必须在 session 创建时打标并贯穿 run/message，不能靠事后按账号猜。
- 真实数据接入要用 outbox + 幂等 + HMAC，避免业务事务被 webhook 拖垮，也避免重复入库。
- 测试通过率和生产真实指标必须分开算，否则两边都不可信。
