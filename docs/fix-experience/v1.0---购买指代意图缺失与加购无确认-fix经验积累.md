# v1.0---购买指代意图缺失与加购无确认-fix经验积累

## 现象

- 用户先收到商品推荐，再说“帮我购买第一款”，AI 回复“当前会话没有可操作的商品。之前为您推荐过……”，没有执行加购。
- “帮我推荐一下空调”召回了冰箱、台灯等完全不相关商品。
- 多规格商品回复“规格序号”后无法继续选中规格；数量 > 1 或金额较高时加购直接执行，没有二次确认。

## 根因

1. `IntentRouter` 的 ADDCART 规则只覆盖“加购/加入购物车/来一份/直接拍/再来/再加”等，没有覆盖“购买/买/要第 N 款/这个/它”，
   “帮我购买第一款”被归为 PRESALE，走商品检索；检索无新结果时回退为“之前推荐过”的追问话术。
2. `ProductConstraintParser` 没有“空调”品类，检索退化为泛化召回，且没有二级词过滤，导致不相关商品进入卡片。
3. `pickSku` 只匹配规格标题/参数，不解析“第一个/规格 1”这类序号。
4. 加购工具是 `WRITE_LOW`，默认直接执行；确认机制只覆盖订单取消、确认收货、售后等高风险写操作。

## 修复

- `IntentRouter` 增加“购买/买/要/拿/来/下单/拍下 + 第 N 款/这个/那个/它/这款/同款”的确定性加购规则；
  保留“想买手机推荐”走售前，避免误判。
- `ProductConstraintParser` 增加“空调”品类及 `needsTermFilter/matchesTerm`，无空调商品时明确告知，不再回填无关卡片。
- `AgentGraphOrchestrator.pickSku` / `ChatOrchestrator.pickSku` 支持“第一个/第 2 款/规格 1/选 1”。
- 新增 `CartConfirmationPolicy`：数量 > 1 或 单价×数量 ≥ 500 元时生成 `PendingAction(addToCart)`；
  单规格、1 件、金额低于阈值直接加购。
- `PendingActionService.summary(addToCart)` 展示商品、规格、数量、单价；前端 `AiChatView` 复用现有确认卡。
- `ChatController` 支持文字“确认/好的/可以/执行”和“取消/不用了/算了”，与确认按钮走同一执行路径。
- `application.yaml` 增加 `agent.cart.confirm-amount-threshold`，默认 500，可配置。

## 回归

- `IntentRouterTest`：新增“帮我购买第一款/就买第二个/我要这个/买它”4 条断言。
- `ProductConstraintTest`：新增“空调”品类与 term filter 断言。
- 既有 200 条 Golden：graph 200/200、legacy 200/200 保持不变。
- 手工验证：单规格低金额直接加购；数量 2/金额 ≥ 500 弹确认卡；按钮与文字确认均成功；取消后购物车不变。

## 经验

- 指代类购买意图必须用确定性规则兜底，不能依赖 LLM 分类；规则要覆盖“第 N 款/这个/它”这类短指令。
- 新品类没有商品时，宁可明确说“没有”，也不能让泛化检索回填无关商品。
- 加购是低风险可逆写，但多件/高金额仍应二次确认；确认策略要可配置，避免一刀切影响转化。
