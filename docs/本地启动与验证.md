# Agent 全链路追踪 · 本地启动与验证

## 1. 前置条件

- Windows + Git Bash
- Python 3.12
- pnpm 11+
- PostgreSQL 17（本机 `D:\environment\postgresql`）
- 可选：本机 zcode `provider_config.json` 中的 wb2api（OpenAI 兼容）配置

## 2. 启动 PostgreSQL

项目已使用 `.local/pgdata` 作为本地数据目录，端口 `55432`。

```bash
cd D:/developertest/ai-studio-platform-main
mkdir -p .local/pgdata .local/pglog
# 首次初始化
D:/environment/postgresql/bin/initdb -D .local/pgdata -U ai -A trust --encoding=UTF8 --locale=C
# 启动
D:/environment/postgresql/bin/pg_ctl -D .local/pgdata -l .local/pglog/postgres.log -o "-p 55432 -h 127.0.0.1" start
# 首次创建数据库
D:/environment/postgresql/bin/createdb -h 127.0.0.1 -p 55432 -U ai ai_test_platform
D:/environment/postgresql/bin/createdb -h 127.0.0.1 -p 55432 -U ai ai_test_platform_test
```

## 6. 一键验证

后端与 mock 服务启动后：

```bash
cd backend
.venv/Scripts/python scripts/verify_agent_trace.py
```

脚本会：

1. 创建 mock target + 用例；
2. 运行失败场景，生成 trace；
3. 调用 wb2api LLM Judge（失败）；
4. 人工评审失败；
5. 创建修复工单；
6. 切换到 `fixed` 场景重跑并 LLM/人工通过；
7. 回归并生成 `docs/fix-experience/v1.0---<名称>-fix经验积累.md`。

预期输出包含 `PASS`、failed run / passed run / fix / doc 路径。

## 8. 常见问题

- **401 或跳登录**：前端 access token 在内存中，整页刷新后会依赖 refresh cookie；确认后端 8000 已启动、`.env` 的 `FRONTEND_URL` 为 `http://localhost:8443`。
- **LLM Judge unavailable**：检查 `JUDGE_API_KEY`、`JUDGE_BASE_URL`、`JUDGE_MODEL`；没有 Key 时判定会明确标为 `unavailable`，不会默认通过。
- **文档路径不对**：`FIX_DOC_DIR` 默认 `../docs/fix-experience`（相对 `backend/`），从 `backend` 启动 uvicorn 即可。
- **端口占用**：`netstat -ano | grep -E ":(8000|8088|8443|55432)"`。
- **Mock 服务 8088 未启动**：HTTP target 会报 `Agent 服务不可用`；mock adapter 不依赖该服务。
